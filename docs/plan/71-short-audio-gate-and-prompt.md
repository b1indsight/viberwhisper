## 1. 初始方案

### 动机、目标与范围

用户提出三项要求：“复用结果，然后补加尾部检测”“概率下调到0.2”“小于2s的段，使用空白例子代替原有的例子prompt”。本方案覆盖桌面 HTTP / Realtime 的门控复用，以及 Realtime 组件 prompt 的短段示例选择；普通 prompt-lab 继续执行同一生产路径。

当前切段器使用持续的 Silero 状态，封段后 HTTP 与 Realtime 又从新状态检测整段。切点处还可能有未送入检测器的小步残余、重采样缓存和不足一帧的分析样本，不能把“暂未检出语音”当成“完整检查后没有语音”。[切段器](../../src/audio/segment.rs)、[流式检测](../../src/audio/vad.rs)、[整段门控](../../src/audio/preprocess.rs)

当前 17 组内置示例放在 `PromptComponents.memory` 末尾，完整 `dictation.prompt` 又具有显式覆盖优先级。不能靠搜索任意自定义文本删除“看起来像示例”的部分。[默认资源](../../assets/dictation-prompt.default.json)、[组合与覆盖](../../src/dictation/config.rs)

此前 94 条短音频实验中，空示例消除了整句示例照抄，但完整匹配下降，动态前文仍会串入。部分关键截短发生在服务原始正文中且上传 PCM 完整，因此本方案不承诺修好所有截短或前文污染。[实验与诊断](https://ampcode.com/artifacts/c47f41ae-a737-4137-aedc-d8b50970106d)

不改变音频裁剪、重叠、增益、30 秒 / 字节上限、800ms 停顿计数、JSON 字段顺序、记忆及确认反馈规则；不增加用户阈值配置、依赖、两阶段模式或通用音频框架。不改个人 config / memory、已安装应用、服务或源 WAV。

### 拟定行为与兼容性

- **复用：** 本段有明确的流式人声证据时，保留能量检查，跳过第二次整段 Silero。尚未确认人声时补检未覆盖尾部；已分析部分不重新推理。
- **补尾：** Pause、Limit、Stop 都覆盖未分析残余。补检使用独立的重采样和 Silero 状态，不刷新或补零后继续使用活动检测器；零只用于分析末帧，不写入源 PCM。
- **不确定：** 无流式证据的离线 / Fixed 输入、检测失败，或仅有跨段边界的阳性帧时，显式回退现有整段门控。回退不算尾部复用成功；整段检测也失败时仍保留识别。保留能量通过且不足 32ms 的现有放行规则。
- **阈值：** 共享 `SPEECH_THRESHOLD` 从 0.3 改为 0.2，仍为 `>=`。本方案建议同时影响切段和最终门控；800ms 计数不变，但概率变化会改变实际停顿切点，需要单独测量。
- **段长：** 按完整源 PCM 段计时，包含捕获的停顿，不含协议补零；24kHz 下 47,999 样本用短示例，48,000 及以上用原示例。小于 100ms 的段仍先选 prompt，再补协议静音。
- **示例：** 内置 / 显式拆分了示例的组件 prompt 在短段只保留下面一个例子，其他规则与输出顺序不变；长段和文字后处理保持原示例。

```text
示例：音频中没有可辨认语音时。
回复：{"context":"未知语境","memory_candidates":[],"text":""}
```

- **显式覆盖：** 完整 `dictation.prompt`（包括空字符串）、lab `--prompt-file` / `--no-prompt` 保持字面优先，不自动改写。旧组件对象缺少新增 `examples` 字段时也保持原文，不猜测其 `memory` 中的示例边界。当前个人配置有完整字符串覆盖，因此新默认策略不会自动作用于这份个人配置；测试使用隔离副本的组件策略。[覆盖入口](../../src/dictation/config.rs)、[lab 候选覆盖](../../src/prompt_lab/production.rs)
- **HTTP prompt：** HTTP STT 使用独立的 `transcription.prompt`，没有这 17 组 Realtime 示例，不套用 Realtime JSON 示例；只共享门控和阈值变化。[HTTP 配置与请求](../../src/transcriber/api.rs)

### 技术设计与接口

#### 记录分数对应的源位置，在独立状态中补尾

- `src/audio/vad.rs`：新增内部 `FrameScore { source_start: u64, source_end: u64, probability: f32 }`，表示一帧对应的全录音源样本半开区间及概率。`StreamingVad` 增加 `processed_frames: u64`，保存已完成分析帧数；采样率沿用其 resampler，不重复保存。
  - `push(&mut self, pcm: &[i16]) -> Result<Vec<FrameScore>>`：保持跨包 / 跨段状态，用分析游标与采样率映射源位置，采用保守整数边界，不按分数返回时刻归属。
  - `preview_tail(&self, extra_source: &[i16]) -> Result<Vec<FrameScore>>`：复制现有 recurrent state、64 样本 context 和不足 512 的 pending；接收独立重采样尾部，补零最后不足一帧的分析输入。返回新增尾帧，不重复已完成帧，也不改变 live 状态。
- `src/audio.rs`：`PcmResampler` 增加 `previous_input: Vec<f32>`，只保留最近实际送入 FFT 的一个完整输入块，尚无输入块时为空。
  - `preview_finish(&self, extra_source: &[i16]) -> Result<Vec<i16>>`：重建同参数 FFT 实例，重放最近一个完整块以恢复 overlap，丢弃预热输出，再复制 pending、skip、输入 / 输出计数，并沿用现有 finish 算法补齐尾部。同采样率路径直接透传。该方法只预览新增输出，不复制整次录音或第三方私有状态。
  - 此方案依据 rubato 0.16.2 的 overlap 由最后一个块独立覆盖这一实现特征。它仍须以“独立对照实例实际 flush”的输出逐字节相等、且预览不改变后续输出这两项检查验证；咨询意见不能替代运行验证。若不能满足，停止采用此优化并记录原因，不悄悄换成任意长度预热或宣称整段回退就是尾部补检。
- `src/audio/segment.rs`：新增全录音 `source_samples: u64`、当前段起点 `segment_start: u64` 及 `ambiguous_speech: bool`。保留既有段长与停顿计数；前一段延迟返回的分数不能标记下一段有声。阳性帧必须位于本段内才可直接复用；跨段阳性只标记不确定，若本段没有其他明确阳性则回退整段门控。
  - `Cut` 增加 `speech: Option<bool>`：`Some(true)` 为明确人声，`Some(false)` 为完成本段分析及必要补尾后无语音，`None` 为 Fixed / 失败 / 边界不确定。
  - `finish(&mut self) -> Option<Cut>`：在清除 step 前生成尾段证据；此时 `offset` 为 0，表示没有额外输入包样本。非空尾段只关闭一次；内部切点不清除 live 分析残余。
  - 只要本段已明确有声，就不必为存在性门控继续计算尾帧；live 检测仍正常推进以决定后续停顿。

#### 证据跟随不可变音频，保持识别接口不变

- `src/audio/chunk.rs`：`WavChunk` 增加仅供 crate 内部使用的 `speech: Option<bool>`；普通编码 / 文件构造默认 `None`。新增 `with_speech(self, speech: Option<bool>) -> Self`，只附加元数据，不改 WAV 字节，不序列化进文件。
- `src/audio/recorder.rs`：`pending_cut` 改为 `Option<(usize, Option<bool>)>`，同时保留绝对切点和对应证据；编码失败重试与 stop 的多个切点都不能丢失或错配证据。编码成功后附在对应 `WavChunk`，`ReadyChunk`、队列及 `Transcriber::transcribe` 接口不扩展。
- `src/audio/preprocess.rs`：现有两个门控入口签名不变，先沿用能量检查，再读取 chunk 证据；有证据直接判定，没有证据才完整分析。HTTP 响度准备和重试载荷规则保持原样；不把元数据附着后的错误音频当成合法缓存。
- `src/dictation/engine.rs`：`finish_segment(&mut self, connection: &mut Connection, memory: &mut Memory, speech: Option<bool>) -> Result<()>` 接收所属 Cut 的证据，按现有源 PCM 编码并附加元数据；静音仍 clear，识别仍串行。补零前保存 `source_samples = self.segment.len()` 交给 transport。

#### 只拆出示例，每次 response 明确选择完整指令

- `assets/dictation-prompt.default.json`、`config.example.json`：将原 `memory` 末尾的 17 组示例原样移到新增可选字段 `examples: Option<String>`，其余组件不改。`#[serde(default)]` 使旧七字段对象继续有效；缺失字段为 `None`，不自动补入内置示例。
- `src/dictation/config.rs`：保留 `compose(&self) -> String` 和 `DictationConfig::prompt(&self) -> String` 作为正常版；新增 `compose_for_segment(&self, short: bool) -> String` 和 `DictationConfig::short_prompt(&self) -> Option<String>`。仅明确拥有独立 `examples` 的组件生成短版；完整 override 返回 `None`。文字后处理重新拼回正常示例。两种有效指令都校验现有长度限制；正常版及默认文字后处理须与基线逐字相同。
- `src/dictation/transport.rs`：Connection 保留正常 `instructions: String`，增加 `short_instructions: Option<String>`。`finish`、`finish_streaming` 及内部 `finish_inner` 在现有参数中增加 `source_samples: usize`；固定 24kHz 下用 `<48_000` 选择完整指令，每次 `response.create` 都明确发送。
  - session 级 instructions 置空，避免短响应仍从 session 继承正常版示例；正常段的 response 指令本身不变。用同一 socket 的长 / 短 / 长请求和真实服务抓包验证，不能只检查本地字符串。

#### lab 身份覆盖条件策略，不扩张执行管线

- `src/prompt_lab/dataset.rs`：`SttSnapshot` 增加向后可读的 `short_prompt: Option<String>`，正常版继续保存在 `prompt`；`Some` 表示固定的源时长 `<2s` 策略，显式 literal override 为 `None`。
- `src/prompt_lab/production.rs`、`regression.rs`、`review.rs`：报告执行身份使用新的 `desktop-recognition-short-audio-v1`，标识 0.2 / 复用补尾行为；prompt digest 覆盖正常版、短版和选择策略。旧单 prompt 报告仍可读，但不同执行身份不能冒充同策略 A/B 或沿用旧门禁结论，必须重跑匹配的基线。
- 普通 lab 不增加另一套分段器、冻结时钟或禁用反馈。逐段 PCM、实际 prompt hash、reuse / tail / full 路径及推理次数用本轮临时诊断与抓包保存，不为了这次实验新增永久通用 trace 管线。
- `docs/dictation.md`、音频 / lab 架构说明及 changelog 同步适用范围与覆盖优先级；历史方案 [67](67-pause-aware-recognition-segments.md)、[68](68-two-stage-realtime-transcription.md) 保留，本记录是新组合需求的后续方案。

### 备选方案、成本与风险

- **继续两次整段检测：** 最简单，但不满足复用要求；保留为无证据和不确定时的明确回退。
- **切点刷新 live 检测器：** 会把为边界补的零写进持续状态，改变后续检测，不采用。
- **新状态独立扫描几百毫秒尾部：** 需要另选预热时长，且丢失已有 recurrent state；优先采用可验证的单块重建与状态复制。
- **全局替换所有示例 / 扫描自定义字符串：** 前者不符合仅短段替换，后者会误删用户规则，不采用。
- 代价是每个活动 resampler 多保留一个输入块，必要尾检重建 FFT 及复制小量检测状态；用实际分析次数、CPU 和耗时验证收益，不能仅凭“少跑一次”宣称整体更快。
- 持续状态与原整段新状态分类可能不同；0.2 也可能增加噪声误通过、改变切点。报告误丢语音和噪声误通过两侧，不要求所有新旧分类一致，也不隐藏不利差异。
- 短段仍保留动态参考，因此没有隔离全部前文污染；空示例本身也可能增加空输出。需要分别观察，不能把无示例复制当作完整识别正确。

### 验证与消融策略

以下均为待实施后的验证计划，本轮未运行：

- **重采样与真实 VAD：** 16 / 24 / 44.1 / 48kHz，辅以支持范围端点；没有上一块、输入块前后 ±1 样本、pending 为 0 / 511、step 残余、连续预览、纯零 flush。独立对照真正 finish，比较预览新增 PCM 和概率，再继续流验证未预览对照；信号使用非对称尾部，避免静音掩盖状态错误。
- **切段与门控：** Pause / Limit / Stop、一次 push 多切点、阳性来自前段且当前静音、只在尾部出现语音、全静音与可闻噪声；验证已确认语音不重复整段推理、未确认尾部确实被检查。故障明确回退，编码失败后证据不串段；相同 PCM 改变分包后样本、门控与边界合同不变。
- **边界及兼容：** 0.1999 / 0.2 / 0.3；47,999 / 48,000 / 48,001 样本；协议补零不改变选择；同一 socket 长 / 短 / 长；默认长版和文字后处理逐字不变；完整 override、空 override、旧组件和显式候选覆盖不被改写。HTTP 无新 JSON prompt，实际 WAV / 上传 PCM 不因证据改变。
- **质量集：** 使用既有 94 条 ≤2s 音频和两个较长对照；清单含 93 条 <2s 和一条恰好 2s，因此不要求 94 条都走短版。增加静音、噪声、轻声 / 尾音、>2s 正常口述及含停顿的长录音；后者验证切段后的真实短段，不能只测独立短文件。[既有清单与回归记录](https://ampcode.com/artifacts/c47f41ae-a737-4137-aedc-d8b50970106d)
- **消融：** 同一服务 / 模型、源 PCM、样本顺序和隔离初态，对比旧基线、仅复用补尾且保留 0.3、再改 0.2、最后启用条件示例；另做“复用阳性但不补尾、未知整段回退”和全正常 / 全空示例对照，区分尾检和时长分流的作用。常规评测保持生产时间、连续连接、正常记忆 / 自动确认；每组从相同只读初态副本重启，不修改源记忆。
- **记录口径：** 语音误拦截、噪声误通过、请求数 / 推理帧数 / 耗时、切点、严格 JSON、完整匹配、包含缺失输出的统一 WER、示例照抄及前文复用；缺失 final 保留在分母，原生 incomplete 不强行应用复核。补尾降低重复检测与模型识别质量分别报告。
- **检查：** `cargo +1.99.1 fmt --check`、`cargo +1.99.1 build --locked`、`cargo +1.99.1 test --locked --all-features`、`cargo +1.99.1 clippy --locked --all-targets --all-features -- -D warnings`。复用现有测试文件，永久测试只保护门控、源样本、兼容与请求合同；计数和消融探针临时使用后删除。

### 待批准与实施问题

批准本方案时需明确接受两项兼容决策：0.2 同时用于切段与门控；完整自定义 prompt 保持覆盖，因此个人配置不会自动启用短示例。本方案不请求修改个人文件。

## 2. PR 变更时间线

### 2026-11-12：复用源区间证据，在独立状态中补尾

- **触发与状态：** 为避免封段后重新执行整段 Silero，同时不漏掉重采样缓存和不足一帧的尾音，已在 `audio::{vad,segment,recorder,preprocess,chunk}` 与 Realtime engine 实施证据传递。
- **实现：** 流式帧携带源半开区间，前段延迟阳性不能放行后段；跨边界阳性且无本段独立证据时回退完整门控。已确认语音不补检；未知段复制 recurrent state、context 和 pending，重建重采样器后仅检测新增尾帧。证据随不可变 WAV 保存，编码失败重试和 stop 不丢失或串段。
