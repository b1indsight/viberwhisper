# 52 - 流式听写与语境记忆

PR：[#138](https://github.com/b1indsight/viberwhisper/pull/138)（草稿）。
客户端已实现；真实模型兼容性、识别质量和延迟仍待验证。

## 目标与范围

增加可选的 Realtime 路径，在一次音频推理中完成听写、保守纠错、标点、语境判断和词语提取。
只修改客户端；沿用现有热键、录音、托盘、历史和文字输入流程。默认关闭，保留 HTTP STT 路径。
配置和使用方式见 [README](../../README.md#realtime-听写与语境记忆)，模块与协议细节见
[架构文档](../architecture/dictation.md)。

## 最终决策

| 决策 | 原因与实现边界 |
|---|---|
| 使用通用 Realtime 多轮连接 | 不适配 Gemma 当前的单轮或累计 60 秒限制；服务能力不足由服务端增强。客户端按 30 秒分段，成功录音复用连接。 |
| 单次推理只返回 `text`、`context`、`memory_candidates` | 最终文字直接交付，候选仅含 `kind`、`text`。不再调用独立 LLM 清理，不保留逐字稿、证据字段或文本差异回退。纠错质量依赖提示词与真实语音评测。 |
| 语境由音频自动判断，记忆仅通过配置文件管理 | 短期观察滚动保留 24 小时，单独保存于 `dictation-memory.json`；长期词表在 `memory.long_term` 中维护，不自动过期或由模型改写。不增加前台设置和管理入口。 |
| 有界、按语境提供上下文 | 保留近期历史、候选词及独立录音支持次数，优先提供手工长期词表。不确定语境不学习；未知语境引用和无效候选被丢弃，有效文字仍可交付。 |
| 复用现有会话、音频与拼接代码 | `SessionOrchestrator` 统一会话身份、路由和开始/结束/取消；Realtime worker 负责连接和连续音频处理。WAV 校验、重采样归 audio；各入口共用 `text::merge_texts` 和 `transcription.language`，保留重复口述。 |
| 故障与主动取消采用不同交付语义 | 网络、录音或清理失败保留已完成且验证通过的分段；主动取消不交付。两者均丢弃本次记忆更新，退役失败连接，不重放已提交音频。 |
| prompt-lab 只迭代完整基础提示词 | 复用既有评测、指标、报告与语义审阅流程。评测关闭个人记忆；`--prompt-file` 替换全文，`--no-prompt` 清空指令，采用后写入 `dictation.prompt`。原始录音采集仍走 HTTP STT。 |
| 测试只覆盖关键行为和明确回归 | 保留连接复用、重复口述、截断、取消竞态、故障部分结果、心跳、记忆过期和重采样边界。固定协议步骤共用测试辅助函数，不另建评测或测试框架。 |

## 验证结果

- 最近一次完整测试：222 项通过、2 项忽略；Clippy all-targets、格式及差异空白检查通过。
- 此后仅精简测试搭建：相关 14 项通过、1 项真实服务测试忽略；测试代码净减少 59 行，测试数量不变。
- 模拟服务覆盖同连接两次录音共 66 秒、四次响应、事件重放及重复口述；不代表真实模型质量通过。
- 早期测试与消融记录见[精简前记录](https://github.com/b1indsight/viberwhisper/blob/b05ff7b5369f91ced04e1b4827b3cdeeca6a9667/docs/plan/52-contextual-streaming-dictation.md)。已删除机制的验证不作为当前实现的质量保证。

## 待完成

1. **服务联调。** 上次局域网测试建连成功，但 `session.update` 被拒绝，未上传音频。
   服务仅允许最多 2048 输出 token，客户端请求 4096；当时源码还缺少显式 response 输入、
   上下文控制及音频条目删除能力。需服务增强后重测，不采用专用绕行。
2. **真实语音验收。** 验证中文准确率、专有词与跨话题影响、JSON 输出可靠性、提示词对照、
   延迟及长录音吞吐；Windows 实机行为尚未验证。
3. **已知未修复问题。** 默认 URL 仍指向开发局域网地址，与文档中的回环地址不一致；
   反相立体声音频在平均转单声道时可能抵消有效语音。
