# Realtime prompt-lab 语境与记忆校验 — Feature record

**阶段：** 实现、本地验证及独立代码审阅完成；跨平台 CI 状态见 PR。
**PR：** [#142](https://github.com/b1indsight/viberwhisper/pull/142)。

## 1. 初始方案

### 动机与目标

当前 `prompt-lab evaluate` 关闭个人记忆，`OfflineDictation` 每个样本使用冻结记忆，
`Transcriber` 只返回文字。报告因此无法证明实际请求使用了哪些语境，也无法校验
模型返回的 `context`、`memory_candidates` 和后续记忆变化。

此前通过临时 prompt 附加固定语境的实验，在留出集上将 WER 从 27.59% 降至
22.41%，专有名词准确率从 75% 提高至 100%，复跑得到相同输出。但该实验使用
人工术语和模拟历史，不能验证正式结构化输入、记忆学习和检索链路。

本次让 Realtime prompt-lab 使用生产记忆及请求链路，并让输入、输出和校验结果
可复现、可审阅。实验数据位于本地缓存，不作为仓库必须存在的测试资源。

### 范围与验收标准

- 新增 `prompt-lab evaluate --realtime-cases <json>`，显式启用场景评估；仅支持
  已启用的 Realtime backend，HTTP backend 提前报错。
- 无该参数时保持现有关闭个人记忆、独立样本评估的行为。
- 场景从显式种子开始，按指定顺序播放数据集 WAV；复用生产话题选择、记忆学习、
  快照预算、24 小时过期及独立录音支持次数规则。
- 请求的语境通过 `response.create` 的 `input_text` 携带，复用正式 Snapshot，
  不再把参考语境拼进 prompt。
- 每轮记录实际快照、实际任务指令、结构化返回、有效记忆更新和断言结果。
- 校验话题归属、候选术语、记忆学习与后续历史可见性、过期和无关历史污染。
- 场景输入及预期值严格校验；所有断言预期、参考文本和禁止输出内容仅用于本地
  评分，绝不进入请求。
- 不读取或写入日常 `dictation-memory.json`、配置和普通转写历史。

### 用户行为与场景格式

场景文件使用版本化的严格 JSON。每个场景具有唯一 ID、显式初始时钟、可选长期
词表及带时间和来源的短期观察，以及按顺序排列的样本步骤。

每步引用数据集的 ready sample ID，可推进模拟时间，声明可选断言：

- 实际输入快照应包含或不包含的话题、术语和历史。
- 返回 `context` 应为 existing/new/uncertain；existing 必须指向输入中的真实 ID。
- 应提取及不得提取的 `memory_candidates`，按类型和文本检查。
- 本轮完成后应保留或排除的记忆内容、支持次数和历史。
- 转写不得包含的历史专属字符串；更一般的语义污染由 coding-agent 审阅判断。

场景之间独立，步骤之间学习记忆。每个 ready 样本在一次报告中恰好出现一次，
场景文件必须完整覆盖 ready 集合；缺失、重复、pending 或不存在的 ID 在联网前
报错。不同上下文条件通过不同文件单独评估同一数据集，避免重复计权和泄漏。
超出生产长度、数量或快照预算的种子明确报错；生产学习产生的内容仍按原规则
裁剪，报告记录真正发送的快照而非未经裁剪的种子。

示例：第一段录音谈论项目，声明新话题并提取产品名称；第二段引用相同话题，
验证输入包含第一段历史、模型选择 existing、输出仅含第二段内容；推进时钟超过
24 小时后，验证短期历史消失而长期词表仍可用。未知话题 ID 和不合法候选另用
本地服务桩覆盖，避免依赖真实模型偶然输出这些错误。

### 技术设计与模块职责

- `src/prompt_lab/` 新增 Realtime 场景所属模块：负责文件校验、顺序运行、断言和
  场景身份；参考及预期数据与送给模型的输入使用不同类型。
- `src/dictation/memory.rs` 提供 crate 内显式种子、无持久化、可注入时钟的入口；
  复用已有 Memory 学习与快照规则，不再实现第二套检索器。
- `src/dictation/result.rs`、`transport.rs` 提供最小结构化观测入口：校验能看到原始
  context/candidate 字段及被生产解析器丢弃的非法元数据。保留生产交付文字的
  容错策略；校验不能把非法字段被丢弃误认为模型通过了要求。
- `src/dictation/offline.rs` 提供显式场景执行所需的结构化结果，复用 Recording、
  连续重采样及正式 response 输入；不把记忆概念加到通用 HTTP Transcriber。
- `src/core/cli.rs`、`src/core/prompt_lab.rs` 接线新参数和 backend 校验。
- `src/prompt_lab/regression.rs`、`review.rs` 在现有指标、审阅和报告校验基础上加入
  场景结果，避免复制 WER、专有名词或语义评分实现。

报告写入新版本结构，普通与场景运行使用同一报告入口。保留旧报告读取、审阅
及普通运行对比；旧报告不能被解释为完成了语境或记忆校验。
场景报告记录场景文件内容及摘要、每轮实际输入和输出、校验策略版本及结果。
对比要求同一数据集、样本覆盖、backend、模型和校验策略；不同种子与历史输入
允许对比，但在报告中明确列出差异。修改预期断言或步骤顺序必须拒绝直接对比。

传输或转写失败仍产生 incomplete 报告；模型正常返回但语境、候选或记忆断言
失败，保留可审阅结果并使新增校验 gate 失败。该 gate 与现有文字质量 gate 一起
决定 `meets_targets`。本地语义审阅也要检查历史内容补写，不能只看名称命中率。

### 替代方案及理由

继续附加 prompt 最简单，但不能观察正式记忆链路。直接读取个人记忆会让复跑
和隐私边界不稳定。仅支持冻结快照能测试消歧，却无法验证跨轮学习与过期。
因此选择显式隔离场景和生产 Memory；不额外添加通用插件或后台评测服务。

### 成本、风险和控制

场景报告会包含显式提供的历史；文档说明保存位置，沿用密钥及 endpoint 脱敏。
人工词表与样本名称重叠是有意的输入干预，结果只证明给定上下文下的表现，
不声明未见过术语上的泛化。不同场景不共享记忆，避免跨场景串扰。
声明禁止输出的字符串可能误伤当前确实说出的内容，由 fixture 作者负责选择；
更一般的污染仍通过语义审阅判断，不实现推测式自动语义裁决。
报告兼容和结构化观测是主要实现风险，以旧报告和生产容错回归用例保护。

### 实施顺序

1. 定义并验证场景输入、断言和身份；补充示例 fixture。
2. 接入显式种子及模拟时钟，贯通正式输入与结构化结果观测。
3. 接入 CLI、报告、对比与校验 gate，保留旧报告和普通路径行为。
4. 完成服务桩与记忆边界回归，更新 CLI 和架构文档。
5. 串行运行真实 Realtime 消融，完成同一 bookmark/PR 的审阅和 CI。

### 验证及消融

- 用确定性的服务桩确认实际请求的 Snapshot、音频引用和 prompt；确认参考及断言
  不进入请求，失败样本继续收集诊断，原始非法元数据不会被静默计为通过。
- 通过最小多轮场景覆盖新建/已有/不确定话题、候选重复支持、24 小时过期、无关
  话题隔离、记忆预算及历史补写；覆盖普通 HTTP 和无场景 Realtime 的兼容行为。
- 检查报告摘要及派生校验结果、篡改拒绝、对比身份和旧报告兼容。
- 运行 `cargo fmt --check`、相关测试、完整 `cargo test` 和仓库要求的 lint/build。
- 实施后、代码审阅前，用同一批 WAV 和 prompt 比较无上下文、仅词表、词表加历史、
  无关历史四种条件；报告文字指标、记忆及话题校验和污染，不因术语提升就判成功。
- 真实 API 验证串行执行，必要时复跑；没有服务时明确记录未验证项。

### 未决问题及延后工作

无阻塞方案批准的问题。具体 JSON 字段命名和错误呈现可在实施时按现有风格确定。
本 PR 不提供个人记忆导出 UI、自动生成预期答案、默认 prompt 优化或无界场景 DSL。

## 2. PR 变更时间线

### 2026-10-12 — 隔离场景、生产链路和报告 gate

- **触发：** 用户要求实现正式 Realtime 语境与记忆校验。
- **实现：** `prompt_lab/realtime.rs` 定义严格场景、覆盖检查、输入身份与本地断言；
  `dictation/evaluation.rs` 在内存中注入种子和每步时钟，使用正式 Recording、Connection
  和 Memory 学习，不接触个人记忆或配置。生产 Recording 仅在显式评估时收集快照及
  原始输出；原有文字容错和交付策略保持兼容。
- **决定（已实现）：** 用专属 evaluator 承载运行时及记录，而非扩展通用 Transcriber
  或扩大 OfflineDictation 的冻结语义。它复用现有音频分段与记忆规则；业务预期不会
  进入 evaluator，因此不会送入请求。失败录音回滚所有记忆，连接在下一步重建。
- **报告：** schema 2 增加输入、原始元数据、更新后记忆和断言。读取及审阅时重新
  回放状态并计算断言，篡改快照、文字或结果会报错。schema 1 普通报告继续可读，
  不带记忆 gate。对比必须保留场景顺序、时钟和断言，记录每个改变的种子的前后值。
- **校验：** 非法 existing ID、被生产解析器丢弃的候选及 uncertain 携带候选会失败；
  `new` 重复已有标签也失败。正常文字但断言失败仍能完成审阅，其 realtime gate 为
  false；联网或转写失败则报告 incomplete。CLI 显示失败检查数。
- **文档：** README、架构说明及两步 JSON fixture 覆盖学习支持次数、历史和过期。

### 2026-10-12 — 消融及真实 Realtime 验证

- **条件：** 同一留出集 10 个 WAV，同一临时原始任务 prompt、同一 Gemma 模型，
  每个样本独立场景、固定时钟，四组串行运行。词表沿用此前人工开发/模型词表，
  历史为模拟摘要；不含当前参考句、日期、金额或自我纠正答案。
- **证据：** 本地 `.cache/2026-10-11/realtime-prompt-research/memory-validation/` 中
  保存 `prepare.py`、四组 cases、实际 reports、coding-agent review 和 `summary.json`。
  私人 WAV 与缓存不提交到仓库。可用 `prepare.py` 重建场景；统一命令为：

  ```sh
  target/debug/viberwhisper prompt-lab evaluate \
    --dataset .cache/2026-10-11/realtime-prompt-research/holdout \
    --prompt-file .cache/2026-10-11/realtime-prompt-research/memory-validation/prompt.txt \
    --realtime-cases <variant>-cases.json --output <fresh-report>.json \
    --max-wer-percent 10 --min-llm-score 90 --min-proper-noun-percent 95
  ```

| 输入条件 | WER | 专有名词 | 语义分 | Realtime gate |
| --- | ---: | ---: | ---: | --- |
| 无语境 | 27.5862% | 75% | 73.5 | 通过 |
| 仅词表 | 24.1379% | 100% | 80 | 通过 |
| 词表与相关历史 | 25% | 83.3333% | 79 | 通过 |
| 词表与无关历史 | 21.5517% | 100% | 85 | 失败 |

- 无语境与此前基线文字完全一致；无关历史复跑文字也完全一致，校验捕获已有
  “语音和模型服务”被声明为新话题。未观察到历史摘要或无关哨兵被补进文字。
  四组全部无候选，分别有 10/9/9/8 个 uncertain。断言检查实际输入、元数据约定
  和禁止字符串；这四组未声明逐样本语义话题预期，不能把其余通过解释为正确归类。
- **限制：** 所有报告现有文字质量阈值仍失败；相关历史不优于仅词表，无关历史
  文字分更高也不足以通过话题检查。词表与人工标注名称重叠，结果只支持给定上下文
  的干预，不支持未见术语泛化或稳定历史收益。一次提前重叠的词表请求被服务以
  session_unavailable 拒绝，保存 incomplete 诊断并以串行 retry 结果替代。
- **复杂度消融：** 确定性测试对同一初始 Snapshot 和同一输出比较冻结 Memory 与
  可学习 Memory：冻结方式无候选或新历史，可学习方式能检验独立录音支持 1→2。
  同一状态在固定时钟 100 和 86500 的对照只过期短期记忆；成功/失败提交对照证实
  回滚。生产容错解析能保留非法元数据伴随的有效文字，而原始输出校验会失败；
  把保存的失败检查改成通过会被报告重算拒绝。保留种子、时钟、原始观测和回放，
  因为更简单的冻结或仅检查文字方案无法满足跨轮、过期、错误暴露及报告一致性要求。
- **验证：** `cargo test --locked` 239 通过、2 个既有外部服务/私人数据测试忽略；新增
  fixture 和学习消融测试通过。`cargo fmt --check`、`cargo build --locked`、
  `cargo clippy --locked --all-targets -- -D warnings` 及 `git diff --check` 通过。
  独立代码审阅检查提交 `b9b05e9faf24`，无 findings，门禁通过。
