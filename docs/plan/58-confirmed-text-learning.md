# 58 - 确认文本历史与纠错学习 — Feature record

**Stage:** Implemented; validation and review status tracked in PR #151.
**PR:** [#151](https://github.com/b1indsight/viberwhisper/pull/151)（草稿）。

## 1. Initial plan

### Summary and motivation

用户要求 history 保存文本框修改后的输入文字，并结合最终文字与识别结果的 diff、
推理返回的语境和专有词候选，自动积累替换表与记忆，修正以后遇到的识别错误。

目前[确认流程](../../src/ui/preview.rs)已经将编辑后的确认文本用于历史和文字注入；
本次保留并验证这个约定。[Realtime worker](../../src/dictation/engine.rs)仍在识别成功后
立即保存模型产生的记忆，早于用户编辑；最终结果以字符串离开识别模块，用户修改不能
反馈到[记忆模块](../../src/dictation/memory.rs)。

本功能接续已合并的[可编辑预览](57-floating-confirmation-preview.md)和
[语境记忆](52-contextual-streaming-dictation.md)，在新的同一 bookmark / PR 内完成。

### Goals, scope, and success criteria

- macOS、Windows 的桌面 history 与实际传给注入器的确认文本完全一致，保留换行、大小写
  和 Unicode 内容；识别原稿不提前进入 history。
- Realtime 推理的原始文字、语境和候选保留到确认结束；只有用户成功提交后才更新跨录音
  记忆。取消、清空、退出和识别失败不会提交本次学习。
- 明确的专有词纠正生成按语境使用的“误识别词 → 正确词”规则，重启后仍可使用。
  例如模型将项目名识别为“维伯耳语”，用户改为“ViberWhisper”；以后同一语境出现该误词，
  预览直接显示“ViberWhisper”。
- 推理候选须以最终确认文本为依据更新：纠正后的候选替换旧候选，被删掉的候选丢弃；
  未改动的有效候选继续提供短期记忆。
- 不新增一次网络推理，不改变服务端 JSON 契约，也不自动改写用户的 `memory.long_term`。
- 本次学习与按语境自动替换接入有结构化候选的 Realtime 桌面流程。普通 HTTP STT 同样
  保证 history 保存编辑文本；不为它推测缺失的语境和专有词候选。CLI 转换与普通
  prompt-lab 回归继续隔离个人记忆。

### Proposed behavior

1. 识别结束时保留完整、不可变的模型结果，并用已有纠错规则生成初始预览文字。
   区分模型原文、初始预览和用户最终确认文字，避免把自动修改当成人工纠正。
2. 用户编辑后回车，history 和注入器读取同一份确认文本。沿用投递前保存历史的恢复语义，
   同一修订失败重试不重复保存；失败后改文再确认仍保留各次明确确认的修订。
3. 注入器接受投递后，向拥有记忆的 worker 提交一次最终反馈。恢复目标或注入失败时
   保留待确认状态，尚不学习；最终成功采用最后一次确认的文字。
4. worker 结合原文、用户实际修改的区域、分段语境和候选，提取有明确证据的词语纠正，
   原子保存替换表与更新后的记忆。无修改确认不会凭空生成替换规则。
5. 后续将正确词与替换关系作为语境参考；模型仍输出已知误词时，在匹配语境内执行一次
   本地替换再显示预览。规则不串联执行，拉丁词匹配检查词边界，防止改动其他词的一部分。
6. 用户撤回某次自动替换时撤销对应规则；若改成第三个正确词，则以本次人工修改更新
   原误词的目标。自动替换及未改动确认不增加人工纠正的支持次数。

history、托盘最近五条和自动记忆继续承担各自职责：托盘展示确认文本；记忆提供经确认的
语境和术语。学习失败记录错误，不重复已经完成的注入，也不阻止用户继续使用确认文本。

### Technical design and affected modules

**确认反馈与所有权。** Realtime 结果附带可确认或丢弃的不透明反馈句柄，原始分段结果和
候选由 dictation 模块持有；core 负责随结果路由，UI 只交付最终文字，不解释候选。
反馈与录音身份绑定，单次消费；丢弃句柄即放弃本次学习。保留有界待确认状态，反馈提交与
下一次录音有确定顺序，防止新录音读取旧快照。等待反馈时仍处理连接的必要控制消息。
网络和文件写入留在 worker，UI 线程不承担这些工作。

**录音期间的临时记忆。** 长录音的后续分段仍可读取本次临时观察。识别完成不将这份
临时状态直接赋给持久记忆；用户成功确认后，从持久基线和最终文本生成更新。录音、响应
或清理失败的部分文字仍可供用户输入，但沿用失败录音不学习的约定。

**diff 与词语边界。** 在 dictation 内新增内聚的纯纠错模块，采用有计算预算的 Unicode
差异对齐；避免按字节切分或对长文本分配完整二维矩阵。将局部差异扩展到候选的完整词语，
例如“张山 → 张珊”学习全名，不能生成“山 → 珊”的泛化规则。只有唯一对齐、原词与新词
均有效、且能归属语境的替换才进入表。纯标点、格式、数字修改、整段改写、插入、删除、
跨语境歧义及候选缺失不推测成专有词替换。`phrase` 候选用于相关记忆，不自动提升为
永久的通用文字替换。

同时计算原文与最终文本的差异用于词语来源，以及初始预览与最终文本的差异用于证明用户
确实修改过。多段结果保留各自来源；无法可靠对齐的候选丢弃，无法归属的最终片段不写入
某个猜测话题。没有有效语境时不学习。最终确认文字自身不因学习校验而改变。

**持久化与检索。** 扩展现有 `dictation-memory.json` 的版本化原子存储，兼容读取 v1，
新增用户纠错条目，记录语境、原词、正确词、录音来源及时间。旧 v1 观察仍作为模型观察
按原期限处理，不能追认为人工确认。用户纠错与正确术语长期保留，最多 512 条；超额按
最近人工确认时间淘汰。原词和目标沿用最多 80 个 Unicode 字符的术语边界，沿用文件大小
上限。模型观察仍按 24 小时到期；用户配置的长期词表始终由用户维护。

同语境同原词以最新明确人工纠正为准，不同语境分别保存。匹配选择最长的适用词，歧义、
冲突和循环不执行自动替换；一次处理只扫描原始输入，避免 A→B→C 连锁改动。相互重叠
的候选只有唯一可解释时才学习。关闭 `memory.enabled` 同时关闭纠错表的读、写和应用。
沿用最多四个语境和 6000 个序列化字符的快照预算，检索优先级为手工长期词、人工纠错、
模型候选、历史；本地纠错也只使用该响应确定的语境，不做跨话题全局替换。

损坏或未知版本的数据文件沿用不覆盖原文件、使用临时内存的恢复策略。文档说明退出应用
后清理或修改运行数据文件的方法；本次不增加词表管理 UI。

### Alternatives and rationale

- 仅保证 history 为编辑文本，保留现有模型候选学习，改动最少，但不能利用人工纠正，
  也不能稳定修复下次相同的误识别。
- 将所有 diff 片段直接全局替换实现简单，但改写、标点和部分汉字会污染常用词；本方案
  用候选整词与语境限制自动替换，将缺乏证据的修改保留为普通确认文本。
- 只把正确词放进 prompt 可提供提示，但模型仍可能输出同一误词；本方案增加有证据的
  本地替换，确保已经学到的明确错误能自动修正。
- 追加一次 LLM 总结可推断候选缺失的术语，但增加费用、延迟及新的错误来源；本次复用
  已有推理元数据与本地对齐。缺失或含糊的证据不会生成永久规则。
- 独立创建第二个存储文件会增加一致性问题；扩展同一个原子记忆文件，保持一个写入者。

### Costs, risks, and mitigations

人工编辑可能是内容改写，且推理候选不一定准确。严格的整词、语境和唯一对齐条件降低
误学习，代价是部分改词不会自动形成规则；候选缺失时仍需人工再次修改。推理若判断错误
语境，可能无法命中或误用词表，保留可编辑预览与撤回规则的反馈。

长期纠错会保留个人词语，沿用本地数据目录和内容脱敏日志；文档明确期限及清理方式。
增加反馈阶段会影响录音生命周期，须验证丢弃、退出和写入失败都不会阻塞后续会话。
旧版程序不能读取新 schema；回退前需备份并移开新版运行数据，配置和普通 history
不需要迁移。本次不承诺未知术语泛化或未经真实音频验证的识别率提升。

### Implementation order

1. 保留结构化识别结果，接通单次确认反馈，验证 history 与注入读取同一最终文本。
2. 将跨录音记忆提交推迟到成功确认，保留录音内临时学习与失败回滚。
3. 实现候选整词对齐、用户修改证据、规则撤销与语境内单次替换。
4. 扩展记忆 schema、长期纠错检索和快照预算，兼容已有文件及禁用开关。
5. 完成闭环回放、跨平台检查和文档，执行消融后进入代码审阅；沿用同一 bookmark / PR。

### Validation and ablation strategy

- **history 与生命周期：** 初始文案编辑成中英混合及多行文字后，历史、托盘和注入载荷
  一致；同修订重试去重；改文重试采用新文本；取消、清空、退出、失败和过期回调不学习。
- **纠错闭环：** 固定模型输出错项目名及候选，人工纠正后下一录音自动修正；重启加载仍
  生效；不同语境、词内子串、数字标点和模糊改写保持原文；撤回自动替换后不再错误命中。
  覆盖多候选、多段、Unicode、规则冲突和重复反馈，确认自动结果不自增人工支持。
- **记忆兼容：** v1 加载、v2 重载、损坏文件不覆盖、禁用读写应用、模型观察过期但人工
  规则保留、容量限制及手工长期词优先。CLI、原始采集与普通回归不读取个人纠错表。
- **检查：** 按 [CONTRIBUTING](../../CONTRIBUTING.md) 执行格式、Rust 测试和 Clippy；
  integration feature 验证共享确认流程，Windows 构建与原生路径由对应 CI 验证。
- **消融：** 使用同样的确定性识别响应和确认编辑，对比“无用户反馈”“仅正确词提示”
  与“反馈加本地替换”；分别证明候选更新及重复误词的自动修正。移除语境/整词限制，
  对照无关语境、单字修改和词内子串用例；移除反馈去重，验证重试不会重复学习。
- **时机与边界：** 消融在实现后、自动代码审阅前执行；修复后复跑受影响检查。服务桩
  只能证明客户端行为，真实音频质量需另用可用的同一批 WAV 比较，未执行则明确记录。

### Open questions and deferred work

批准前需确认上述默认选择：人工纠错长期保存、按语境自动应用；首次仅对 Realtime
结构化结果学习，候选缺失不猜测；history 沿用投递前保存已确认修订的恢复语义。
具体 diff 实现和内部句柄形式在实现时依据现有类型选择，不增加对外配置项。

延后 HTTP 无候选场景的自动词语提取、整段改写学习、跨语境规则推广和图形化词表管理。

### [001] — 2026-10-16 — 接通最终确认文本、持久纠错与记忆提交

- **背景与实际变更：** history 已使用编辑后的确认文本，本次保留其投递前保存、修订级

- **实现：** `engine` 保留录音内临时学习，但不在识别完成时提交跨录音状态。等待确认时
  处理连接控制消息，收到反馈后更新并保存，再处理下一录音；确认工作线程最多等两秒
  取得写入应答。学习失败只报告错误，不重发已注入的文字。

  歧义；后者跳过学习。按候选完整词语提取修改，用 Unicode 词边界限制匹配，避免
  汉字单字泛化和拉丁词内替换。初始预览与最终文本用于区分人工修改和自动结果。
  修改自动结果为第三个名字会更新原误词，改回原文会撤销规则；同次录音出现不同目标
  拼写时撤销而不任选一项。仅 proper_noun 产生永久规则，phrase 保持短期观察。
- **存储与兼容：** schema 2 增加最多 512 项人工纠错与来源时间，兼容加载 v1 观察；
  纠错不因 24 小时期限或系统时钟回退消失。保留配置长期词的优先级、四语境/6000 字符
  快照预算、原子写入、禁用开关及损坏文件不覆盖策略。默认 prompt 与配置示例说明
  `corrections` 的含义；用户已有 prompt 不自动改写。

### [002] — 2026-10-16 — 纠错机制的消融比较

**设置：** 在同一正式实现上逐项临时移除机制，以相同固定识别输出与人工编辑运行以下
回归，再恢复源文件。基线 `cargo test --locked --lib dictation::correction::tests -q`
为 9 项通过；表中每个简化版本均实际运行并在对应行为断言处失败（退出码 101），

| 简化版本 | 运行的回归 | 实际失败与保留理由 |
