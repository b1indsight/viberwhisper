# 53 - 可配置的 Realtime 提示词组件

**阶段：** 实现与本地验证完成，提交代码审阅与 CI。
**PR：** [#140](https://github.com/b1indsight/viberwhisper/pull/140)。

## 1. 初始计划

### 背景与目标

当前 `src/dictation/config.rs` 将完整听写提示词放在 Rust 的 `DEFAULT_PROMPT` 中。
用户配置的 `dictation.prompt` 可以替换全文，但语言、数字格式、口述清理、JSON、语境和
记忆规则混在同一字符串里，修改其中一种用途时容易影响其他规则。

本次按用户要求新开 PR：将默认正文移入 JSON 配置资源，并提供按用途编辑的组件配置。
代码仅保留组件读取、校验、选择和固定顺序组合；以后修改正文无需修改 Rust。
沿用 [PR #139](https://github.com/b1indsight/viberwhisper/pull/139) 已采用的正文和约束，
不在此次拆分中重新润色提示词或改变模型输出协议。

### 范围与成功标准

- Rust 源码中不再保存默认提示词正文。
- 本机配置 `dictation.prompt_components` 支持独立修改各用途组件；重启后用于实时录音、
  离线转换和 prompt-lab。无需重新编译即可更新已安装应用的提示词。
- 默认正文的维护来源为 `assets/dictation-prompt.default.json`，配置示例展示完整组件。
- 保留既有完整字符串覆盖、空字符串禁用以及 prompt-lab 临时全文覆盖的语义。
- 保留总长度不超过 4096 个 Unicode 字符的约束，报告记录实际发送的组合全文。
- 不增加模板变量、脚本、远程拉取、热重载、组件任意重排或专用管理 CLI。

### 拟定使用方式

在 `viberwhisper config path` 返回的同一个 `config.json` 中配置：

```json
"dictation": {
  "prompt": null,
  "prompt_components": {
    "task": "当前音频的任务与忠实转写原则",
    "language": "中国大陆简体中文 zh-CN 与外语保留规则",
    "numbers": "数量、金额、日期、时间的阿拉伯数字格式规则",
    "cleanup": "填充词、自我修正、原措辞与语气保留规则",
    "output_format": "JSON 字段、顺序、转义和静音输出要求",
    "context": "已有、新建、不确定语境的选择规则",
    "memory": "词语候选的内容、类型和长度限制"
  }
}
```

以上字符串仅展示字段用途；实现后的示例文件填写实际默认正文。
用户修改 `numbers` 就能改变数字写法，其他组件保持原样。

组合顺序固定为 `task → language → numbers → cleanup → output_format → context → memory`。
每个非空组件去掉首尾空白后，以换行分隔；显式空白组件不参与组合。
此字符串拼接不会解释配置中的引号、花括号或反斜杠，也不执行内容。

来源选择规则：

| 配置 | 使用方式 |
|---|---|
| `prompt` 与 `prompt_components` 都为 null 或未填写 | 使用 JSON 资源中的默认组件 |
| `prompt_components` 为完整对象，`prompt` 为 null | 按固定顺序组合用户组件 |
| `prompt` 为字符串，`prompt_components` 为 null | 完整使用该字符串；空字符串清空指令 |
| 两者均显式设置 | 返回配置错误，避免编辑组件却被旧字符串覆盖 |

组件对象必须包含七个字符串字段；未知键、缺失字段、非字符串值均报告具体错误，
不静默补回默认值。要只改一个组件，先复制示例中的完整对象再修改该项；不引入
部分覆盖与隐式深合并。原有仅含 `prompt` 的配置继续有效。

### 技术设计与受影响模块

- `assets/dictation-prompt.default.json`：唯一维护默认正文的配置资源，保存七个组件。
  由构建内嵌该数据资源，保证 macOS、Windows 单文件应用均能取得初始默认值，避免
  依赖工作目录或额外安装步骤。发布新内置默认值仍需发布新版；已安装用户直接修改
  本机组件配置即可覆盖，无需编译。Rust 不复制正文。
- `src/dictation/config.rs`：移除 `DEFAULT_PROMPT`，新增模块所属的严格组件类型，保留
  旧 `prompt` 字段并增加可选组件对象。统一组合入口返回拥有的完整字符串，校验冲突
  以及最终长度；内置资源由相同类型解析，资源格式错误作为开发缺陷提前验证。
  本次规模优先保留在所属模块，不为七项拼接创建通用模板框架。
- `src/dictation/transport.rs`、`offline.rs`：复用组合入口；连接配置、每次 response
  指令与报告元数据均使用同一全文，不让组装规则分散到不同入口。
- `src/core/prompt_lab.rs`：`--prompt-file` 与 `--no-prompt` 设置临时全文覆盖时，同时
  清除内存中的组件选择，避免触发双方同时配置的冲突；磁盘配置保持不变。
- `config.example.json`、`README.md`、`docs/architecture/dictation.md` 与
  `docs/architecture/prompt-lab.md`：说明组件用途、默认来源、冲突规则、重启生效及
  临时全文覆盖。配置 schema 仍为 v3，新增可选字段即可保持旧文档兼容。

### 迁移与替代方案

默认配置使用资源正文；示例配置展示完整组件，方便直接编辑。配置类型的组件字段默认
为 null，避免旧配置省略该字段时与既有全文覆盖产生冲突。读取旧配置时不自动写回。
已有完整字符串覆盖不自动拆分，避免误判用户自定义段落的用途；用户可
保留它，或将 `prompt` 设为 null 后复制默认组件。

本机当前覆盖全文由此前调优设置。实现阶段按已确认的相同正文迁移为七个组件，备份
旧配置、验证所有其他设置不变，并确认旧全文的规则均保留。

- 继续仅用一个字符串：操作简单，但无法按用途维护，未满足此次要求。
- 每个组件放一个独立文件：可避免 JSON 字符串转义，但增加文件查找、部署和缺失文件
  处理。选择现有配置文件中的组件对象，复用跨平台配置存储。
- 任意有序组件数组或模板引擎：更灵活，但本次七项用途已明确；固定字段减少误排和
  拼接逻辑，后续确有新用途时再扩展。

### 成本、风险与边界

JSON 中多行正文需要转义；提供可直接复制的完整示例，不增加编辑器或转换命令。
既有完整字符串覆盖必须显式清空后才能使用组件，冲突通过错误提示说明。
分段和换行会改变 prompt 哈希，既有报告仍保留原全文；对照继续按既有身份规则校验。
组件拆分不保证模型完全遵守简体、自我修正或专名规则，也不修复服务端模型质量。

5. 在此 bookmark、此 PR 上完成独立代码审阅和 CI；不另开实施 PR。

### 验证与消融

- 本地确定性测试覆盖默认资源可读、七项固定顺序、空白项、JSON/Unicode 字符不被
  插值、未知/缺失字段、双重配置冲突、旧空字符串覆盖和 4096 字符边界。
- 接口测试验证配置组件用于报告元数据，临时全文与无指令模式完整替换组合结果，
  不读取参考答案或改写配置文件；保留现有实时和离线关键测试。
- 运行 `cargo test --locked`、`cargo fmt --check`、Clippy 与差异空白检查。
- 实施后、独立审阅前做消融：在相同配置和 WAV 上分别使用组件组合与将其全文作为
  `--prompt-file` 覆盖，先验证实际请求指令与报告哈希完全一致；若真实服务就绪，
  对同一 ready 数据集各做一次全量评测并审阅，记录 JSON 失败及语义差异，不把采样
  波动误称为组装问题。另删除数字组件验证其他正文不变且报告反映这一选择。
- 不改写数据集参考文本来改善 WER，数字字形差异按原策略记录。

### 待确认与后续范围

本方案待用户批准：以现有 `config.json` 为唯一运行时编辑入口，默认正文来自 JSON
数据资源；保留全文覆盖但禁止同时配置组件。实现期间可调整字段注释、局部类型命名
和测试组织，不能自行改动上述兼容性和来源选择规则。

热重载、组件文件导入导出、部分组件继承、多模型提示词预设均留待以后。
